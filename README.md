# AntiSpamBee

AntiSpamBee — Telegram-бот модерации рекламы и спама. Он анализирует сообщения,
bio, личный канал пользователя и публичные реакции, сохраняет объяснимые сигналы
и выполняет действия через надёжную очередь.

## Что уже работает

- защищённый Telegram webhook с ограничением размера и secret token;
- NATS JetStream с durable consumer и дедупликацией по Telegram `update_id`;
- PostgreSQL-события, detector signals, решения, действия и audit log;
- реклама работы, adult/порно, VPN, казино, крипты, займов и обычные промо;
- короткие объявления без ссылок: услуги разработки, набор трафферов/«ворк»,
  торговля аккаунтами и идентификаторами, продажа GPT Plus;
- скрытые `text_link`, URL и базовая нормализация обфускации;
- разделённые и смешанные кириллическо-латинские ключевые слова, а также `t[.]me`;
- сообщения от имени канала, `channel_post` и `edited_channel_post`;
- локальный OCR изображений через Tesseract `rus+eng` под флагом `OCR_ENABLED`;
- анализ bio, username, личного канала и его последних публикаций;
- проверка профиля пользователя, поставившего реакцию;
- flood, повторяющиеся сообщения и история предыдущих нарушений;
- OpenRouter `~typesafe/jev-latest`: уверенный сигнал удаляет рекламу, а бан требует независимого подтверждения;
- allowlist, пользовательские жалобы и Telegram-команды модераторов;
- идемпотентный Action Worker с lease, retry, `retry_after`, reconciliation и DLQ.
- privacy-safe диагностика входа: тип update, длины текста/OCR, наличие ссылки,
  виды медиа и SHA-256 отпечаток без сохранения исходной переписки.

## Политика действий

```text
risk < 0.90       → ALLOW
risk >= 0.90      → DELETE_MESSAGE при подтверждённой рекламе; иначе REVIEW
подтверждённый adult-канал или мошенническое предложение в канале + STRICT + автобан → DELETE_MESSAGE и BAN_USER
```

Автоматическое действие дополнительно требует confidence `>= 0.90`, evidence
coverage `>= 0.50`, разрешённую policy и непривилегированного пользователя.
Для удаления необходимы рекламные признаки самого сообщения либо подтверждённый
рекламный или запрещённый канал в режиме `STRICT`. Ссылка, маркер `18+`,
обычное название канала и bio сами по себе не разрешают удаление.
Явная порнографическая/эротическая тематика в названии или описании канала,
подтверждённый adult-пост либо мошенническое предложение в отдельном посте
разрешают автобан в `STRICT` при включённом `autoban_enabled`.
Завуалированный adult-канал также распознаётся по сочетанию интимного названия
с флиртующим/adult-эмодзи, предложения контента «без цензуры», доступа по заявке
и приватного Telegram-приглашения в одном посте. Одна фраза «без цензуры»
или название «Мой секрет» недостаточны.
Также подтверждается сочетание названия «Приват Милфы», предложения стриптиза
на камеру и приватного Telegram-приглашения в одном посте.
Не требуется реклама в каждом из пяти последних постов: обычные публикации
и медиа без подписи не отменяют найденное подтверждение. Эта проверка использует
текст и подписи, а содержимое фото и видео не классифицирует.
Мошеннические признаки: предложение удвоить деньги/раскрутить депозит,
гарантированная прибыль без риска с призывом связаться или перевести деньги,
оплата доступа к работе и комиссия/налог за получение выигрыша.
Предупреждения о мошенниках и образовательные обсуждения исключаются;
администраторы, владелец и allowlist защищены от автоматического удаления и бана. Ошибка
проверки статуса пользователя приводит к повторной обработке события.
Перед каждой попыткой автоматического действия Action Worker повторно читает
настройки чата и allowlist, после проверки статуса пользователя. Если действие
больше не разрешено, оно отменяется; ошибка чтения настроек откладывает попытку.
Ручные команды модераторов сохраняют отдельный источник полномочий.

Последовательный Moderation Worker получает из NATS по одному событию, чтобы
следующие сообщения не тратили AckWait в локальном буфере.
Во время обработки события Moderation Worker отправляет NATS `InProgress`
каждые 10 секунд; общий срок попытки ограничен 90 секундами. При повторной
доставке уже сохранённого решения анализ и внешние запросы пропускаются.
Команды изменения защиты, allow/unallow и привязки группы атомарно сохраняют
настройки, решение и подтверждение в отдельной очереди ответов. Action Worker
повторяет доставку подтверждения без повторного изменения настроек; повтор
сохранённой старой команды не отменяет результат более поздней команды.
Старые записи команд переходят на этот путь без повторного применения настроек.
Информационные команды с непосредственным ответом, включая history, исключены
из раннего пропуска; их текущий путь доставки сохранён.
Временная ошибка профиля (`429`, `5xx`, сетевой timeout) также повторяется,
если сообщение ещё не распознано как реклама; уже подтверждённая текстовая
реклама удаляется без ожидания профильного API.

Jev включается только при наличии `OPENROUTER_API_KEY`. Уверенный модельный
сигнал ограничен delete-only риском `0.97`; до `1.00` он повышается только при
независимом подтверждении детерминированным фильтром.
В каждый запрос Jev передаётся справочная политика коротких объявлений: услуги,
«ворк», трафферы, торговля аккаунтами/идентификаторами и GPT Plus, с девятью
рекламными примерами и контрольными нейтральными примерами. Это контекст запроса,
а не обучение весов модели. Справочные примеры не входят в `message_passages`
и не могут служить доказательством против автора текущего сообщения.

OCR включается через `OCR_ENABLED=true`. По умолчанию загрузка Telegram-файла
ограничена 8 МБ, распознавание — 12 секундами, язык — `rus+eng`. Production
образ moderation worker уже содержит Tesseract и оба языковых набора. При
ошибке OCR событие повторяется и не превращается в молчаливый `ALLOW`.

Поток выполнения:

```text
Telegram → Gateway → JetStream → Detectors → Decision Engine
                                      ↓
PostgreSQL ← signals + decision + queued action
                                      ↓
                            Action Worker → Telegram
```

## Telegram-интерфейс

- `/start`, `/help` — подробный справочник и кнопка «Добавить в группу»;
- `/report` — пожаловаться, отправив команду ответом на сообщение;
- `/status` — текущий режим защиты;
- `/history CHAT_ID` — последние 5 сохранённых решений в ЛС (ID группы указан в `/status`);
- `/protection observe|soft|standard|strict` — изменить режим;
- `/allow`, `/unallow` — управление allowlist ответом на сообщение;
- `/warn`, `/mute`, `/ban` — действие модератора ответом на сообщение;
- `/unban USER_ID` — снять блокировку по Telegram ID.

Кнопка добавления открывает системный выбор группы Telegram и запрашивает только
права удаления сообщений и ограничения участников. После подтверждённого
успешного бана бот публикует в защищаемой группе уведомление с Telegram ID
заблокированного пользователя.

`cmd/setup-webhook` одновременно регистрирует webhook и заполняет нативное меню
команд Telegram, которое открывается кнопкой `/`.

Административные команды проверяют статус вызывающего пользователя через
`getChatMember`. `/ban` и `/mute` попадают в Action Worker, а не вызывают
разрушительный Telegram API напрямую.

Режимы: `OBSERVE` и `SOFT` оставляют решение модератору, `STANDARD` разрешает
удаление явной рекламы. `STRICT` также удаляет сообщения автора с подтверждённым
рекламным каналом: каждый пост в выборке (до пяти последних) должен содержать
полное рекламное предложение заработка, adult-контента, VPN, казино, инвестиций
или займов. Для вакансий обязательны сумма оплаты и контактный призыв.
Личный или музыкальный контент, публикации без доступного текста, предупреждения
о мошенниках и неоднозначное описание канала исключают это автоматическое правило.
Обычное название канала, нейтральная биография и история срабатываний сами по
себе не разрешают удаление.
Администраторы, владелец, анонимные администраторы, зарегистрированные каналы
администраторов и автоматические перепосты связанного канала защищены.
Если реального автора сообщения нельзя установить, оно остаётся на проверку.
Права автора перепроверяются Action Worker непосредственно перед удалением и баном;
ошибка проверки откладывает действие, а действие для администратора отменяется.
Старые действия, созданные только по профилю, также отменяются.
Политика `message-evidence-v8` разрешает автобан только в `STRICT` для подтверждённого
рекламного порноканала: все доступные посты в выборке должны рекламировать взрослый
контент. Маркировка 18+ в названии или описании учитывается вместе с предложением
«горячих роликов», призывом получить доступ и ссылкой в самом посте.
Поддерживаются маркировки с пробелами и Unicode-символами (`18 +`, `１８＋`).
Упоминания интимных видео в новостях, названия альбомов `XXX` и ссылки на
платформы сами по себе не считаются рекламой взрослого контента. Для рекламы
канала нужен явный призыв вступить или подписаться; упоминание «в нашем канале»
со ссылкой недостаточно. Confidence и покрытие берутся из конкретного сигнала,
который разрешает действие. Анализ поведения применяется только к реальному
пользователю, а служебные авторы Telegram и сообщения от имени каналов пропускаются.
Бан требует confidence `>= 0.98`, полного покрытия доказательств и включённого
`autoban_enabled`; при отключённом автобане разрешается только удаление сообщения.
Реклама вакансий, VPN и другие категории автоматически к бану не приводят.
Ручной `/ban` администратора остаётся доступным.
Сигналы не складываются до «100%».
JEV оценивает текст, подпись и OCR сообщения. Для смысловой проверки профилей и
изображений можно задать `OPENROUTER_CONTENT_MODEL=openai/gpt-4.1-mini`.
`OPENROUTER_CONTENT_CHAT_ID` ограничивает этот режим одной группой.
В этом режиме OpenRouter получает также публичную биографию, тексты последних
публикаций личного канала, до двух изображений из его публичных постов
(до 2 МиБ каждое) и изображения сообщений до 4 МиБ. Запросы требуют
маршрут без сбора и хранения данных поставщиком. Доказательство в тексте модели
сверяется с указанным источником. Подтверждённая реклама в профиле разрешает
удаление комментариев в `STRICT`; явная реклама в сообщении доступна также
в `STANDARD`.

`AUTOBAN_ADVERTISING_CHAT_ID` включает бан за подтверждённую рекламу в выбранной
группе в режиме `STRICT` при включённом автобане. Если локальным детекторам
достаточно доказательств, бот сразу ставит в очередь удаление и бан. Если вывод
сделала модель, `OPENROUTER_BAN_MODEL` проверяет тот же источник. При расхождении
или сбое второй проверки сообщение остаётся на ручной проверке. Баны в этом
режиме записываются в журнал без отдельного объявления в общем чате.

`MODERATION_OPERATIONS_CHAT_ID` включает личные карточки проверки для выбранной
группы. Действующий привязанный администратор может оставить сообщение или
поставить его на ручное удаление. Первая отметка сохраняется в журнале до
истечения срока хранения доказательств. `scripts/export-evaluation.sql` экспортирует
такие отметки как человеческие метки. Перед оценкой сгруппируйте повторы по кампаниям.

Совпадения контактов, ссылок и идентификаторов изображений Telegram сохраняются
в виде ключевых хешей на срок до суток. Совпадение у другого автора с подтверждённым
спамом за последние 45 минут отправляет публикацию на ручную проверку. Для оповещений
бот каждые 20 секунд проверяет очередь, повторные сбои классификации и ошибки
действий Telegram. Бот отправляет одно оповещение каждого типа за 15 минут.
Ограничение сохраняется при перезапуске.
Технические отказы распознавания записываются для оповещений отдельно от
модераторских карточек. Если резервная модель уверенно пропускает простой текст
без изображения и дополнительных данных профиля, бот завершает обработку без повторов.

После автоматического удаления бот отправляет в личные сообщения администратору,
добавившему бота в группу, `@username` автора (либо ID при отсутствии username),
текст удаления и причину. Администратор должен предварительно открыть личный чат
с ботом и отправить `/start`: иначе Telegram запрещает боту написать первым. Для
групп, в которые бот был добавлен до включения этой функции, администратор может
один раз выполнить `/protection strict` в группе — это назначит его получателем.

Для новых решений REVIEW и действий журнал сохраняет исходные текст/подпись,
OCR, контекст профиля, сигналы, версию политики и доступные сведения о версии модели
на 30 дней. Длинные поля ограничены, факт сокращения отмечается в снимке.
Старые удалённые тексты не восстанавливаются. `/history` требует и привязку,
и актуальные права администратора; личный ID не извлекается из анонимного сообщения.

Уведомление об успешном удалении сохраняется транзакционно в отдельную очередь.
Временные ошибки повторяются до 5 попыток с учётом Telegram retry_after;
окончательный сбой виден в `moderation_notification_outbox`. Перед отправкой
перепроверяются привязка и права получателя. Повтор доставки не повторяет удаление.
После неоднозначного сетевого сбоя уведомление может прийти повторно:
Telegram sendMessage не предоставляет ключ идемпотентности в этом клиенте.
Просроченные снимки/уведомления очищаются action-worker каждую минуту пакетами
по 100 строк; при остановленном worker просроченный журнал всё равно недоступен.

Для удаления сообщений и реакций боту необходимо право
`can_delete_messages`, для ban/mute — `can_restrict_members`. Webhook должен
включать `message_reaction`; setup-команда делает это автоматически.

## Локальный запуск

Требования: Go 1.23+, Docker и Docker Compose. Для локального запуска OCR без
Docker дополнительно нужен Tesseract с языками `rus` и `eng`.

```bash
docker compose up -d
cp .env.example .env
# Заполните Telegram-параметры. OPENROUTER_API_KEY можно оставить пустым.
set -a
. ./.env
set +a
```

Запустите три процесса:

```bash
go run ./cmd/gateway
go run ./cmd/moderation-worker
go run ./cmd/action-worker
```

После публикации HTTPS endpoint зарегистрируйте webhook:

```bash
go run ./cmd/setup-webhook
```

Health endpoints:

- gateway: `:8080/healthz`, `:8080/readyz`;
- action worker: `:8081/healthz`, `:8081/readyz`;
- moderation worker: `:8082/healthz`, `:8082/readyz`, `:8082/metrics`.

## Production Compose

Задайте настоящий `POSTGRES_PASSWORD` и секреты в `.env`, затем:

```bash
docker compose -f compose.prod.yml up -d --build
```

Сервис `migrate` применяет ещё не выполненные SQL-миграции до запуска workers.
Не храните `.env` в Git. Если API-ключ когда-либо публиковался в чате или Git,
его необходимо отозвать и создать новый.

## Проверка

```bash
go test -race ./...
go vet ./...
go build ./cmd/gateway
go build ./cmd/moderation-worker
go build ./cmd/action-worker
go build ./cmd/setup-webhook
```

CI поднимает PostgreSQL, применяет миграции, запускает integration tests, race
detector, vet и сборку всех команд.

С `TEST_DATABASE_URL` и `TEST_NATS_URL` тест `TestModerationBurst100ThroughDurableQueue`
прогоняет 100 синтетических событий через NATS и PostgreSQL. Telegram и OpenRouter
заменяются заглушками, включая ответ Telegram `429`. Запуск с `-v` показывает
медиану и p95 от начала подачи событий до завершения удаления и бана.

## Ограничения текущего MVP

- визуальная реклама без текста в картинке требует мультимодальной модели. Аватары не анализируются;
- анонимную реакцию `actor_chat` нельзя связать с конкретным пользователем;
- Jev остаётся выключенным без нового безопасно переданного ключа и расширенного размеченного golden set;
- production backup/restore и внешний маршрут апелляции настраиваются отдельно.
